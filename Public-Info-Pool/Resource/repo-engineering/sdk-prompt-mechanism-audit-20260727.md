# Silver Core SDK 提示词-机制一致性审计（P1 / P4 型）

- 日期：2026-07-27（北京时间；UTC+8）
- 类型：repo-engineering
- 审计对象：`silver-core-agent-sdk` v0.85.0 源码（提示词常量 / 工具描述 vs 机制实现）
- 派生自：同日「记忆工具病理四型」分类——P1 机制无规程 / P2 单向镜 / P3 检测无处置 / P4 提示词自伤。
  P2 已由截断纪律批（0.85.0）系统收口并有注册表测试守增量；P3 已由整理规程批（0.84.0）收口。
  本档案补上此前明示「未审计」的 P1 / P4 两型。

## 审计方法与范围声明（先说清查了什么、没查什么）

**P4（提示词与机制相悖）**：逐一核对 SDK 注入的提示词常量（`prompt-fragments.ts` 全部
MEMORY_* 片段与两条 R7 提示词）与 `descriptions.ts` 主要工具描述里的**行为性断言**，对照
其机制实现。方法是断言级抽查而非全文逐句形式化——工具描述总量约 900 行，本轮覆盖记忆
系统全部提示词（100%）与 Read / Grep / Glob / Bash / WebFetch / Workflow / TodoWrite 七个
高频工具描述的容量与截断类断言。

**P1（机制无规程）**：对「带上限或假设纪律的机制」逐个问「harness 是否给了配套规程」。
覆盖记忆系统全部机制与工具层容量机制；**未覆盖**：sessions 转录累积、hooks 匹配器、
subagents 运行时、MCP 层——列入未审计清单，不假装查过。

小学生比喻（P4 型总括）：老师嘴上说「作业写在作业本上」，收作业的机器却只收试卷——学生

## 未审计清单（诚实边界）

sessions 转录累积（有无上限、满了怎么办）· hooks 匹配器与提示词交互 · subagents
运行时的提示词断言 · MCP 工具描述转发层 · `descriptions.ts` 其余工具的非容量类断言。
后续若审，从 sessions 起——它与记忆同为「跨会话持久层」，病理同族概率最高。

## 结论

四型病理处置完毕率：P2 / P3 全收口，P4 实锤三处全修，P1 实锤三处修二挂一（P1-3 并入
A1 待裁）。**机制性守卫已立两道**：截断注册表测试（新截断点必登记）+ 哨兵两档制（新知识
文件不再逼豁免）。「各凭作者自觉」的结构问题在容量纪律这一域已升格为「算得出来」；
提示词-机制一致性尚无自动守卫（形式化难度高），维持人工审计节拍，建议并入月检。

小学生比喻（收尾）：这次不只修了几个坏灯泡，还装了两个总闸报警器——以后哪个新灯泡
不合规格，一插上就响，不用等人巡楼发现。
