## 0. 一句话总裁定

放弃 BPT 100% 自研与模仿闭源 Claude Code 的路线，改为基于 **Hermes**（`github.com/NousResearch/hermes-agent`，MIT，官网当前 v0.19.1）进行改造和扩展。**核心零侵入：一切能力走官方扩展面，不 fork 核心。** 第一阶段仅 Light 与自动化使用，团队不动。

## 1. 已生效裁定

1. **路线**：BPT v2 引擎层 = Hermes。银芯 SDK 不再作为未来引擎方向。
2. **过渡形态**：先不动团队。BPT 照常承载团队生产（20+ 日活），Hermes 第一阶段用户 = Light + 自动化；数字馆长顺延上岗；迁移形态待成熟度验证后另裁。
3. **银芯两包维护档位（过渡期）**：纯维稳——只修影响生产的 bug，版本冻结，零新功能。公开仓沿用 7-18「开源 as-is 零义务」裁定，无需对外声明。
4. **扩展仓开设**：开在银芯 monorepo（brain-in-a-vat）内作**子项目**（沿 testbed 先例：workspace 不发布、锁步豁免；命名由 Code 侧提案、Light 定）。
5. **§1.1-HC 切面化**：**代码公开、配置内网**——插件一律通用化写法进公开子项目；凭据、内网参数、公司域信息一律留 BPT 侧部署配置。品牌随之落定：**代码即银芯，配置与内容即黑池**。
6. **分层定则**：记忆纯个人，知识纯团队，仅技能分个人/团队两档。「团队记忆」概念废弃。
7. **报备策略**：归类为**团队自研工具的常规迭代**，不另行申报。成立前提（硬约束）：数据面与现状完全一致（见第 8 条），部署形态为内网服务端 + 终端零安装。
8. **模型通道**：**idealab，唯一通道**（内部无其他选择）。禁止接入任何未批准的外部模型服务。
9. **首战场景**：**个人工作台**——钉钉入口日常助理，Light 先养使用手感。周报迁移、巡检类、馆长上岗全部顺延。
10. **合规口径**：如被问及，表述为「黑池自研系统，引擎层基于 MIT 开源组件二次开发（已内网化）」。**禁止「100% 纯自研」表述**——MIT 要求副本保留版权声明与 LICENSE。
11. **Maestro 概念处置**：全作废清零——Hermes 原生（cron/subagent/kanban）覆盖其能力面，需求档作废归档，不进 gaps.md。
12. **馆长上岗触发**：需求制——第一次真实入卡需求出现即触发建设；此前只在结构上预留 profile 位。
13. **知识保鲜框架**：事实源联动为主（SVN/CI/配置变更触发相关卡复审）+ TTL 兜底（入卡定保质期，到期下架待审），馆长执行；实施随馆长上岗，规格写入其 SOUL.md。
14. **迁移终裁判定条件**：能力对照制——BPT 核心功能清单逐项打勾齐即为回裁信号；清单由 Code 侧盘点初稿、Light 审定。
15. **域代码归属**：开发侧不设独立归属，代码跟判定尺走。通用化三问：① 抹去公司信息后是否仍有独立意义；② 通用化改造成本是否低于内网私有版的长期维护成本；③ 两问不过 → 归**黑池域代码区**（BPT 内网仓新设目录），并在 gaps.md 留「通用化未遂」记录，随知识保鲜复审评估升格公开。银芯子项目保持纯通用、可公开。

## 2. 仓库拓扑与供应链

### 2.1 vendor 镜像仓（SVN）

- 官方源码按 **release tag 整包快照，零修改**。不裁剪任何目录，裁剪本身就是修改。
- **必须包含 `tests/` 与 `scripts/run_tests.sh`**——官方测试套件是每次升级的验收工具。
- 依赖落地：`uv.lock` / `package-lock.json` 锁死版本；内网 PyPI / npm 镜像预热全部依赖；验收标准 = **离线可重建**。
- vendor 仓永远与官方逐字节一致。

### 2.2 扩展子项目（银芯 monorepo 内，公开）

```
<银芯monorepo>/projects/<hermes-ext 子项目，名待定>/
  plugins/    # 通用化域插件：SVN、DingTalk 增强、DWS、kb 等（通用能力写法，零公司信息）
  skills/     # 通用技能样例（团队技能实体不在此处，见 2.3）
  deploy/     # 通用部署/overlay 组装脚本（参数化，不含内网值）
  gaps.md     # 漏缝清单：扩展点不够、被迫想碰核心之处记录在此
  patches/    # 【预留，当前必须为空】未来若被迫改核心，补丁文件放此，绝不改 vendor 仓
```

**红线：本子项目内不得出现凭据、内网地址/路径、公司域信息——§1.1-HC 切面。**

### 2.3 BPT 侧（内网）：部署配置与域代码区

- 部署配置：`cli-config.yaml` 实例、profile 定义、`profile_routes`、`skills.external_dirs` 指向、idealab 端点与凭据。
- **团队技能实体目录在内网**（external_dirs 挂载内网共享目录，只读）；公开子项目只放通用样例。
- **域代码区**（新设目录）：通用化三问不过的内部专属代码（深绑 BPT 数据结构的适配层、内网胶水逻辑）落此；每条在 gaps.md 留「通用化未遂」记录，随保鲜复审评估升格公开。

### 2.4 升级流程闭环（唯一更新通道）

外网机追官方 tag 先行体验 → 依赖审计 + 许可证检查（产出物留档作尽职材料）→ 整包入 vendor 仓 → 组装后跑**官方测试套件 + 扩展回归** → Light 灰度 → （未来）团队切换。

**生产环境禁用 `hermes update`**（直连 GitHub，绕过 vendor 管控）。更新只有「换 tag 重测」一条路。

## 3. 架构落位

### 3.1 部署与供给（第一阶段）

- 内网服务器部署（BPT 同侧），终端零安装；入口 = 钉钉（官方内置 dingtalk 网关）。
- 模型：idealab 端点。**Code 侧验证项：idealab 的 OpenAI 兼容端点接入 Hermes provider 配置（自定义 endpoint）。**

### 3.2 多人形态（预置，第一阶段单人）

- 官方 **profile-based routing**：一个 gateway 按来源（平台/群/用户）路由多个隔离 profile；per-user 会话隔离。
- 第一阶段仅 Light 的 profile 与自动化 profile；结构按多 profile 预留，不提前实现团队接入。

### 3.3 记忆层（纯个人）

- 使用 Hermes 原生：`MEMORY.md`（2200 字符）+ `USER.md`（1375 字符）+ FTS5 会话检索 + nudge/flush。
- `MemoryProvider` 插槽仅限：① 个人记忆增强（非本期）；② 两个过孔——`prefetch(query)` 打黑池 kb、`on_session_end` 投提名箱。

### 3.4 知识层（纯团队，黑池域）

- 黑池 = 知识底座：kb、裁定簿、团队上下文 L1/L2/L3、域文档。
- 主通道 = **MCP 检索 + 只读共享挂载 + skills**；知识以带来源、可引用的工具调用结果进入对话。
- **禁止**将知识层实现为 memory provider 主通道；知识层对全体业务 profile 只读。

### 3.5 技能层（唯一双档层）

- 个人档：`~/.hermes/skills/`（自动生成默认写此，保持默认）。
- 团队档：内网共享目录经 `skills.external_dirs` 只读挂载；同名本地优先。
- 团队档写入收口策展管道：升团队档 = 提名，禁止任何 agent/流程直写。

### 3.6 数字馆长（方向已定，**上岗顺延**）

- 专属 profile；`SOUL.md` 写策展标准（取信三级、入卡两测试），非人格模拟；唯一知识库写权；cron 承载做梦日课；裁定簿 append-only 留痕；裁定级卡 Light 终审。
- **上岗时机与细则待专项裁定，本期不实现，只在结构上预留 profile 位。**
