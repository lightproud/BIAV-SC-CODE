## §0 结论先行

**PlugMem 与银芯 SDK 记忆实现不是竞品，是两个不同楼层的东西，放在一起比「谁更好」是问错了问题。**

- PlugMem 解决的是「**记什么、怎么组织、怎么找回来**」——记忆的**表示与检索算法**（认知层）。
- 银芯 SDK 解决的是「**工具面长什么样、存储归谁、谁能写谁只能读、写没写成怎么看得见**」——记忆的**协议、存储契约与治理**（工程层）。
- 二者的接缝是干净的：PlugMem 那套东西，在银芯 SDK 的架构里恰好落在 `MemoryStore` 注入点**之外的消费方侧**（黑池的 L3 夜间合成层）。真要用，是「黑池实现一个 PlugMem 味的 store + 离线合成任务」，而不是「SDK 改架构」。

小学生比喻：PlugMem 是「怎么整理笔记本、怎么快速翻到那一页」的方法；银芯 SDK 是「笔记本本身、笔和橡皮、谁允许在哪一页写字、以及本子满没满的检查表」。买了一套整理方法，不代表本子要重做。

## §1 两侧本体核实

### §1.1 PlugMem 是什么（二手采信）

一个**任务无关的插件式长期记忆模块**，核心主张是「以**知识**为记忆的组织与访问单元，而不是以实体或文本块为单元」（这是它与 GraphRAG 系的分界线）。

三张互联的图：

| 记忆类型 | 核心单元 | 结构 | 用途 |
|---|---|---|---|
| 情景 G^E | 事件窗口 | 顺序轨迹 | 溯源 / 校验 |
| 语义 G^S | 命题（propositional） | 概念 ↔ 命题 ↔ 来源 | 事实索引 |
| 程序 G^P | 处方（prescriptive） | 意图 ↔ 处方 ↔ 来源 | 策略复用 |

- **写侧**：原始交互标准化为 (observation, state, action, reward, subgoal) 元组 → LLM 抽命题（带指代消解 / 去重 / 长度约束）→ 按子目标相似度切轨迹、LLM 归纳 (intent, prescription) 对并打**回报分** → 插图。
- **读侧**：LLM 先判该偏重哪类记忆 → 用查询嵌入打分低层节点得候选集 → 逐跳：生成抽象查询（概念 / 意图）打高层节点作**路由信号**，激活相邻低层节点，超预算按相关性 / 重要性剪到 top-K → 直到证据够或到跳数上限。**高层节点只做路由，不进候选**。
- **度量**：以 PMI 定义「决策信息增益」，除以记忆长度得**信息密度（bit/token）**，跨基准可比。
- **自报指标**：LongMemEval 90.2；HotpotQA 79.1 F1 / 91.1 LLM-Judge；WebArena。注入 token：LongMemEval 362.58（对照全上下文 107K、朴素检索 3742.52）、HotpotQA 81.6、WebArena 301。
- **消融**：去结构化 −12.3 个点（75.1→62.8）；去检索最惨（信息密度转负）；去推理模块分数几乎不掉但 token 爆到 9478.59（密度掉 39 倍）。判词是「检索决定记忆有没有用，结构化决定能不能被检索到，推理决定效率」。
- **依赖**：NV-Embed-v2 嵌入服务 + Qwen 本地推理服务 + 部分任务要 OpenAI API。
- **论文未明说的成本**：每情景要几次 LLM 调用没给；WebArena 还插了 23/18/5 条**人工演示**做知识迁移。

小学生比喻：PlugMem 是把一学期的课堂录音，先请一位助教听完写成「知识点卡片」和「解题套路卡片」，再把卡片按概念连成一张网；考试时不翻录音，只顺着网抓几张卡。

### §1.2 银芯 Agent SDK 记忆实现是什么（一手核实）

`silver-core-agent-sdk` v0.79.1，runtime 依赖只有 **zod + fast-glob**（零嵌入、零模型、零常驻进程）。记忆模块 `src/tools/memory/` 共 **9 档 2,758 行**；memory 专项测试 10 档共 **147 个 `it` 用例**（grep 计数：golden 30 / m2 31 / wiring 20 / mounts 17 / audit-r4 15 / health 9 / paths 7 / conformance 轴 7 / read 6 / contract-suite 5）。

面上是与 Anthropic `memory_20250818` **协议等价的六命令工具**（view / create / str_replace / insert / delete / rename），骨子里是四件事：

1. **双装配模式（R2）**：Anthropic 协议下直通官方类型条目 `{type:'memory_20250818', name:'memory'}`（服务端注入定义与协议提示），OpenAI 协议下 SDK 自带六命令 schema + 自注协议片段。两模式**存储产物字节相同**，且已对**实录官方臂线缆**做过字段级差分（fixture `tests/conformance/official-memory-wire.json`）。
2. **存储契约外包（R3 / G2）**：SDK **不知道数据存在哪**。消费方注入 `MemoryStore`，或实现 6 个 `MemoryFileOps` 原语交给 `createMemoryStore()` 白拿参考格式。附**可发布的契约测试套件** `runMemoryStoreContractSuite()` 让第三方自测。并发语义只声明两条（单命令原子性、后写胜），锁与事务明确不进契约。
3. **harness 定下限（G3）**——这是它区别于「靠模型自觉」的地方：
   - **R4 路径穿越防护**：每条命令每个路径在 SDK 层先验，**不信任 store 自防**；23 变体攻击集列入发版门禁。
   - **R6 索引常驻**：会话开头自动注入 `/memories/MEMORY.md` 头部（默认 200 行 / 25,600 字节，先到者胜，截断有明示）。
   - **R7 写时机强制**：压缩折叠前先插一轮写机会（`flushOnCompaction`）；正常收尾跑一轮进度卡更新（`sessionEndUpdate`）。
   - **R8 限额与账单**：64 KB/档、64 档/目录、view 16,000 字符；`metrics.memoryHealth` 逐次计 operations / reads / writes / errors / bytes / 注入 token。
   - **R9 卡片模式**：`schema:'cards'` 下每份记忆必须是 `## 标题` + **结论 / 依据 / 过期条件** 三字段卡（500 字/卡、50 卡/档），非法写入返回**结构化错误重述格式**供模型重试。
4. **治理层 S1–S6**：`mounts` 按会话上下文实例化的读写路由（最具体挂载点优先、只读子树防递归删、祖先目录列表过滤）；`incognito` 一旗降级只读且零持久化；结构化工具调用日志；声明校验器。

外加两件「运维可见性」：
- **`sessionEndUpdate` 状态枚举**（ran / failed / disabled / skipped-abort / skipped-budget / skipped-turns / skipped-interrupt / pending）+ `Query.memoryHealthSnapshot()`——**把「进度卡没写成」变成可编程发现的信号**，直击 BPT 部署回滚事故里那条「每轮重读陈旧卡、重跑验证、再撞预算」的记忆腐烂环。
- **`assessMemoryStoreHealth()`** 五维深扫：目录水位线（软 48 / 硬 64）、腐化（默认 30 天未改，**后端无 mtime 就标 unavailable，绝不编造**）、容量余量、`supersedes:` 链完整性、读写比（只写不读 = 囤积不是记忆）。这是黑池「做梦」整理任务的触发面。

**明确写死的非目标（N2）**：不做向量检索 / 嵌入 / 知识图谱。且给了**量化触发线**（开放问题 Q3）：「评测集检索类题目得分 < 80% **且** 索引常驻已到预算上限」时才重评向量方案。

小学生比喻：银芯 SDK 是学校发的作业本制度——本子什么格式、谁能在谁的本子上写字、一页最多写多少、老师怎么一眼看出谁的本子该整理了。它**故意不规定**你用什么方法整理笔记。

### §1.3 容易被漏掉的第三方：银芯 OKF 知识库导航层

真要给 PlugMem 找同层对照物，银芯里已经有一个，只是不在 SDK 里：`okf/kb_index.json`（**2.05 MB，376 个 concept**，倒排表 + 邻接表）+ `scripts/kb_navigator.py`（396 行）/ `kb_vector.py`（228 行）/ `kb_anchor.py`（148 行）/ `build_kb_index.py`（208 行）。

它与 PlugMem 的形状高度相似——**知识为单元、图上多跳、先锚后扩**：

| PlugMem | 银芯 KB 层 |
|---|---|
| 概念 ↔ 命题 ↔ 来源三层图 | OKF 一概念一文件 + `graph.json` 带类型边 |
| 嵌入打分低层节点 | `kb_vector_search`（Voyage 嵌入，缺 key 优雅降级） |
| 高层节点作路由、逐跳激活邻居 | `kb_activate`（扩散激活）/ `kb_neighbors` |
| 抽象查询 → 低层候选 | `kb_anchor`（脊柱锚定 + 厚锚别名扩词 + 向量捞长尾据锚去杂） |

**但有一条银芯有、PlugMem 论文没有的东西**：反稻草人的对照臂纪律。`scripts/kb_ab.py` 强制拿**最强 grep** 当对照臂并把「KB 不劣于 grep + 联想题严格胜」写成回归测试；`kb_qual.py` 专测 hit@k 测不出的四维；`kb_golden_gen.py` 从图的带类型边自动生成数百题黄金集；`kb_semantic_ab.py` 做零共享 token 的换说法召回铁证。PlugMem 的基线是 GraphRAG / HippoRAG2 / AWM 这类同族系统，**没有「朴素 grep 打得过你吗」这条羞辱线**。

小学生比喻：PlugMem 和同类高级方法比谁跑得快；银芯 KB 层每次都得先跟「走路」比一次，跑不过走路就别自称跑步机。

## §2 逐维对照

| 维度 | PlugMem | 银芯 Agent SDK 记忆 |
|---|---|---|
| **所在层** | 记忆的表示与检索算法 | 记忆的工具协议 + 存储契约 + 治理 |
| **记忆单元** | 命题 / 处方（LLM 抽取的知识单元） | **文件**（`/memories/**`，内容由模型自写；cards 模式下强制三字段卡） |
| **组织结构** | 三张互联图 + 缓存嵌入 + 溯源边 | 目录树 + `MEMORY.md` 索引 + `supersedes:` 前言约定 |
| **检索** | 嵌入打分 + 多跳图激活 + 剪枝 + LLM 条件化 | **模型自己 view**（无检索引擎），读侧兜底 = 索引常驻头部 |
| **写时机** | 会话重置 / 压缩前自动存轨迹，再离线结构化 | **同款**：`flushOnCompaction` + `sessionEndUpdate`（在线一轮，无离线结构化） |
| **依赖** | 嵌入服务 + LLM 抽取 + 图存储 | zod + fast-glob，**零嵌入零常驻** |
| **成本形态** | 每情景 N 次 LLM 调用 + 常驻嵌入 / 图；换来注入 token 降 1–2 个数量级 | 近零处理成本；注入 token 靠**硬预算**压（索引 25 KB / 单档 64 KB / view 16 K） |
| **质量下限** | 靠 LLM 抽取质量（模型好则好） | 靠 harness（schema 校验 + 限额 + 路径门禁 + 写时机强制），**不依赖模型自觉** |
| **安全 / 多租户** | 论文未涉及 | S1 挂载点路由 + S2 隐身 + 双端 rename 门 + 祖先列表过滤 + 23 变体穿越攻击集 |
| **可观测** | 信息密度 bit/token（评测期指标） | 逐次 `memoryHealth` 计数 + 写回状态枚举 + 五维存储体检（**运行期指标**） |
| **数据主权** | 图与嵌入在系统内 | **SDK 零感知存储介质**——对齐 §1.1-HC，记忆数据永不出内网 |
| **实证纪律** | 与同族方法比（GraphRAG / HippoRAG2 / AWM） | 与**官方实录线缆**做字节级差分；契约套件可发布给第三方自测 |

## §3 核心判词：分层错位，接缝干净

三条：

1. **它们不冲突，因为压根不在一层。** 银芯 SDK 的 `MemoryStore` 注入点 + 黑池三层架构（人写指令层 > 模型自写层 > 离线合成层）里，**PlugMem 精确落在第 3 层「离线合成」**——`docs/MEMORY.md` §8.3 早已写明「等 1、2 层跑一个月、有真实数据后再建」，§5 P2 还预留了「导出/导入整个 store 快照」的接口位给夜间批处理。PlugMem 若要进来，是**填这个坑**，不是掀桌子。

   小学生比喻：作业本制度和「暑假请家教帮你把一学期笔记重抄成知识卡」不打架——家教干的活正好是本子制度留白的那部分。

2. **PlugMem 的消融结论，反过来印证了银芯 SDK 的一个已知缺口。** 它的判词是「检索决定记忆有没有用」；而银芯 SDK 的读侧**只有两条腿**——模型自己 `view` + `MEMORY.md` 头部常驻，**没有第三条检索腿**。这不是疏忽，是 N2 明写的非目标 + Q3 明写的触发线。所以正确的说法不是「银芯 SDK 少了检索」，而是「银芯 SDK **押注在目录规模没大到需要检索之前**，用硬预算 + 索引常驻扛住」。**这个押注什么时候破，Q3 已经给了判据。**

   小学生比喻：书包里就十本书时，翻找不需要图书检索系统；但书塞到两百本还坚持翻找，就是嘴硬了。Q3 就是那条「几本书算多」的刻度线。

3. **PlugMem 最贵的部分，恰好是银芯最不能进的部分。** 它靠 LLM 抽取 + 嵌入服务 + 常驻图，而 SDK 的设计原则第 3 条是「零新依赖」，G2 是「存储完全客户端化、SDK 零感知」。把 PlugMem 塞进 SDK，等于让 SDK 长出模型调用与嵌入服务依赖——**直接破掉 drop-in 纪律与数据主权承诺**。它只能长在消费方侧（黑池 store 实现 + 夜间任务），这与 §1.1-HC 防火墙方向一致（银芯出规范，黑池自己实现，不回流）。

   小学生比喻：本子制度可以说「建议每周整理一次」，但不能规定「必须请我们指定的家教」——那样本子就卖不出去了，还得把学生家的地址交给家教。

## §4 值得从 PlugMem 借的三点（按可落地性排序）

**借 1：把「处方」这一类记忆显式化（对应 R9 卡片模式的一次扩容）。**
现在 cards 模式只有一种卡型：结论 / 依据 / 过期条件——这是纯**命题型**（propositional）。PlugMem 的分野提醒：**「怎么做成的」（prescriptive，意图 + 步骤 + 回报分）是另一种记忆，塞进结论字段会被磨平**。银芯已有的 `pitfalls` 协议（症状 / 根因 / 修复 / 规避）其实就是半个处方卡，只是没有意图键与回报分，也没进 cards schema。
落地成本：`cards.ts` 加一个卡型 + 校验分支，零新依赖。
小学生比喻：错题本上「答案是 42」和「这类题先画图再列式，我这么做对了 8 次」是两种笔记，不该挤在同一栏。

**借 2：信息密度作为记忆层的验收指标（补 G4 的空缺）。**
G4 写着「可度量——能回答记忆效果是否变好」，§8.5 给的方案是 20 题回忆集 + 账单。但**账单只算分子（token 花了多少），回忆集只算分母（答对没有），没人把两者相除**。PlugMem 的 bit/token 密度正是那个商。银芯不必照抄 PMI（要算 P_base 得跑两次模型），但可以取**廉价代理量**：`评测得分增量 / 注入 token 数`，逐月对同一评测集回归。
落地成本：`memoryHealth` 的字段已经全在（`indexInjectionTokens` / bytesRead），缺的是评测集侧的除法。
小学生比喻：光记「今天背了 3 小时」没意义，光记「考了 80 分」也没意义，要看**每小时换来几分**。

**借 3：写侧「先标准化再抽取」的两段式，用来给黑池 L3 层写规范。**
PlugMem 的写路径是「原始轨迹 → 标准化元组 → LLM 抽知识」，而不是「原始轨迹 → LLM 直接写卡」。中间那一步标准化，是它去重 / 指代消解 / 溯源边能成立的原因。银芯 SDK 的 S3 结构化工具调用日志 + sessions 模块**已经产出了近似的标准化底料**，黑池 L3 层若要建，规范里应当写死「读 S3 记录而非读自由文本转录」。
落地成本：文档级（写进 §8 搬运包），SDK 零改动。
小学生比喻：先把一整天的流水账整理成「几点、做了什么、结果如何」的表格，再让助教提炼；直接让助教读流水账，提炼出来的东西没法互相对账。

## §5 不建议照搬的三点

**不借 1：把图与嵌入塞进 SDK。** 破 N2、破零依赖、破数据主权，且 Q3 的触发线尚未触发（当前没有「检索题 < 80% 且索引到预算上限」的证据）。要动，先出证据。
小学生比喻：没量过体温就先吃退烧药。

**不借 2：LLM 抽取作为写侧强制路径。** 银芯的设计原则是「模型定上限，harness 定下限」；LLM 抽取质量随模型波动，正是**上限**手段。它可以做增强，不能做下限。PlugMem 自己也承认依赖模型质量，且 WebArena 还得插 23/18/5 条人工演示才转得动。
小学生比喻：请助教帮忙整理可以，但不能把「作业必须交」这条规矩改成「助教有空才交」。

**不借 3：它的评测结论直接当银芯的决策依据。** 三个基准（长程对话 QA / 多跳检索 / 网页智能体）没有一个是银芯 SDK 的真实负载（跨会话工程协作 + 长任务续跑）。§8.5 那 20 题自建回忆集，对银芯的判据价值高于 LongMemEval 的 90.2。
小学生比喻：别人在标准田径场跑出的成绩，说明不了他在你家山路上跑得动。

## §6 银芯已经领先的三点（不必向 PlugMem 看齐）

1. **诚实降级贯穿到底**：无 mtime 就把腐化标 `unavailable` 而非编数；扫描到界标 `truncatedScan` 而非静默少报；写回没跑成有八态枚举可读。PlugMem 论文侧未见任何失败模式分析。
   小学生比喻：体温计没电了就说「没测成」，而不是随手写 36.5。
2. **安全与多租户是实现级的，不是提示词级的**：挂载点在 store 调用**之前**、路径校验在 store **之前**、递归删的只读子树守卫、祖先目录列表过滤。这一整块 PlugMem 完全空白。
   小学生比喻：门锁装在门上，不是写张「请勿入内」贴纸。
3. **对照臂纪律**（§1.3 的 KB 层）：拿最强 grep 当羞辱线并写成回归测试。学术侧普遍缺这一条。
   小学生比喻：先证明你比走路快，再谈跑鞋牌子。
