## 一、外部事实：这次改了什么

MCP 2026-07-28 是该协议第 5 个版本（2024-11-05 → 2025-03-26 → 2025-06-18 → 2025-11-25 →
2026-07-28），官方称其为迄今最大改版。核心变化（SEP 编号可回核官方 changelog）：

| 变化 | SEP | 要点 |
|---|---|---|
| 协议核心无状态化 | SEP-2575 | 废除 `initialize`/`notifications/initialized` 握手；每个请求在 `_meta` 里自带 `io.modelcontextprotocol/protocolVersion` / `clientCapabilities` / `clientInfo`；版本不匹配返回 `UnsupportedProtocolVersionError`（-32022） |
| 废除传输层会话 | SEP-2567 | `Mcp-Session-Id` 头移除；跨调用状态改为「服务端发显式句柄、模型当普通参数传回」 |
| `server/discover` | SEP-2575 | 服务端必须实现；客户端可先探测版本/能力，亦作 stdio 向后兼容探针 |
| MRTR 多轮请求 | SEP-2322 | 取代服务端主动请求（`roots/list` / `sampling/createMessage` / `elicitation/create`）：服务端返回 `resultType: "input_required"` + `inputRequests`，客户端带 `inputResponses` 重试原请求 |
| `resultType` 必填 | SEP-2322 | 所有 result 带 `"complete"` 或 `"input_required"`；旧服务端缺省时客户端必须按 `"complete"` 处理 |
| `subscriptions/listen` | SEP-2575 | 取代 HTTP GET 流 + `resources/subscribe`：单条长驻 POST 响应流承载订阅通知 |
| 头路由 + 可缓存列表 | SEP-2243 / SEP-2549 | Streamable HTTP POST 必带 `Mcp-Method` / `Mcp-Name` 头；`tools/list` 等必带 `ttlMs` + `cacheScope` |
| SSE 可续传移除 | SEP-2575 | `Last-Event-ID` / SSE event id 移除，断流即重发新请求 |
| 授权强化 | SEP-2468 / SEP-2352 / SEP-837 | RFC 9207 `iss` 校验、凭证绑定发行方、DCR `application_type`；DCR 本身转向 Client ID Metadata Documents |
| 扩展框架转正 | SEP-2133 / SEP-2663 | `extensions` 能力字段；**tasks 移出核心协议**成官方扩展 `io.modelcontextprotocol/tasks` |
| **三能力弃用** | SEP-2577 | **Roots / Sampling / Logging 进入弃用轨道**（至少 12 个月移除窗口，新实现不应再加支持）；legacy HTTP+SSE 传输同步转正式弃用（SEP-2596） |

生态动向：Anthropic 官宣在 Claude 全线产品滚动跟进；Cloudflare Agents SDK 已给出兼容范式
——先 `server/discover` 探测，探不到就在同一连接上回退旧 `initialize` 握手；MCP C# SDK 发 v2.0
实现新版。生态迁移预计以「双模共存一年」为主节奏（弃用政策明文最少 12 个月窗口）。

## 二、银芯接触面盘点（本会话代码扫描，file:line 可回核）

全仓恰好两个互不共码的 MCP 面：

1. **Python 服务端** `scripts/mcp_server.py`（biav-sc-memory）：官方 `mcp` 包 FastMCP 高层 API
   （`:39` / `:61`），**stdio 传输**（`:377`），**仅 tools 能力**（11 工具），仓内零协议版本
   硬编码——版本协商 100% 委托给 `mcp` 包；依赖声明 `scripts/requirements.txt:5` 为
   **`mcp>=1.0.0` 无上限地板**。注册面 `.mcp.json`（stdio，8 行）。
2. **TypeScript 客户端** `projects/silver-core-sdk/src/mcp/`（8 文件，干净重实现，零
   `@modelcontextprotocol/*` 依赖）：宣告版本 `2025-06-18`（`protocol.ts:44`），接受列表
   `['2025-06-18','2025-03-26','2024-11-05','2024-10-07']`（`protocol.ts:58-63`）；
   **`2025-11-25` 系刻意排除**（未实现 tasks 异步面，不宣告未落地语义，`protocol.ts:34-43`）。
   传输：stdio 全量 + Streamable HTTP 全量（含 `Mcp-Session-Id` 跟踪与 404 重握手）+
   in-process `sdk` 型；legacy SSE 显式不实现（构造即抛）。能力：tools 全量 + resources
   （list/read）+ elicitation（应答服务端主动 `elicitation/create`）；**prompts / sampling /
   roots / logging 均未实现**，未知服务端请求回 `-32601`。
3. **maestro-sdk / testbed：零 MCP 代码**，仅把 `mcpServers` 选项原样透传给 agent SDK。

## 三、影响评估（按面分级）

### 面 1：biav-sc-memory 服务端 —— 影响「低」，一项卫生动作

- 本地 stdio + 仅 tools，恰好避开全部震中：无状态化主打 Streamable HTTP 横向扩展；被弃用的
  roots / sampling / logging 本服务端一项都没用；tools 核心语义本版未破坏。
- 版本协商全权委托官方 `mcp` 包：包升级到支持 2026-07-28 时（`server/discover`、`_meta`
  版本携带、`resultType` 填充）本仓**零代码自动获得**；客户端侧（Claude Code）对旧版
  服务端有 ≥12 个月兼容窗口 + `server/discover` 作 stdio 兼容探针。
- **唯一风险点**：`mcp>=1.0.0` 无上限地板。官方 Python SDK 若随新规范发不兼容大版本
  （FastMCP API 变动），云容器**装机时**即换血，坏点会出现在「某天新会话突然起不来」而非
  代码变更时。建议加上限 pin（如 `mcp>=1.0.0,<2`），等验证过再抬（建议项，未实施）。

### 面 2：silver-core-sdk 客户端 —— 影响「中·主战场」，但不急于动工

这是全仓唯一手写 MCP 协议栈的地方，也是使命#2 对黑池的输出物，规范换代的结构性工作量都在这。

1. **锁步压力**：SDK 的保真基准是官方 Claude Code。Anthropic 已官宣全线跟进，上游客户端
   开始发 `server/discover` 探测 / `_meta` 版本携带之日，就是 SDK 线上行为指纹漂移之时。
   届时 Module F 需要 Cloudflare 同款双模：探测到 2026-07-28 走无状态面，否则同连接回退
   `initialize` 旧握手。
2. **涉改清单**（届时的工作量轮廓）：无状态请求形态（`_meta` 三件套）+ `server/discover`
   + MRTR 客户端支持 + `resultType` 解析（旧服务端缺省按 complete）+ `subscriptions/listen`
   + HTTP 必带 `Mcp-Method`/`Mcp-Name` 头 + 错误码迁移（-32022 等新段位；资源未找到
   -32002→-32602）。现有 `Mcp-Session-Id` 跟踪与 404 重握手逻辑降级为 legacy 路径专用。
3. **MRTR 与 elicitation**：SDK 现按 2025-06-18 语义应答服务端主动 `elicitation/create`；
   新版把这一整类服务端主动请求换成 MRTR（`input_required` + 重试携带）。旧路径在弃用窗口内
   继续可用，但新式服务端只会说 MRTR——这是双模里客户端侧真正的新增语义。
4. **三项「不做即正确」的红利**：SDK 一直未实现 roots / sampling / logging，此前审计视其为
   能力缺口；SEP-2577 弃用三者后，**缺口翻转为正确的前瞻姿态**——新规范明文「新实现不应再加
   支持」。legacy SSE 传输拒绝实现同理（SEP-2596 正式弃用）。四项全部从欠账变资产，零成本。
5. **战略捷径：跳过 2025-11-25**。SDK 当初拒宣 2025-11-25 的唯一理由是 tasks 异步面未实现；
   2026-07-28 已把 tasks 移出核心协议成可选扩展。**直接以 2026-07-28 为下一个目标版本，
   比补课 2025-11-25 再升级便宜一档**——中间版本的核心必做项（tasks）在新版里不再是必做项。
6. **节奏**：不建议抢跑。触发条件 = 上游 Claude Code 实测开始使用新握手 / 新头（conformance
   线上指纹或 `refresh-claude-code-prompts.yml` 周检可见），届时立需求档动工；生态弃用窗口
   12 个月，被动等待期零风险。

### 面 3：maestro-sdk / testbed —— 无直接影响

零 MCP 代码，纯透传。唯一动作是届时随 agent SDK 锁步版本前进（家族既有节拍，零新增负担）。

### 面 4：BPT（黑池侧）—— 单向输出物视角，一条时间线风险

依 §1.1-HC 防火墙，本评估仅基于银芯侧已知事实：BPT 以 tarball pin 消费 silver-core-sdk
0.3x（CLAUDE.md §1.2）。含义：

- **今天零影响**：pin 版客户端讲 2025-06-18，存量 MCP 服务端在 ≥12 个月弃用窗口内全部继续
  互通；生态服务端将双模共存。
- **时间线风险**：弃用窗口走完后，生态会出现「只讲无状态、不再答旧 `initialize`」的服务端
  （尤以托管 Streamable HTTP 网关为先，stdio 本地件最后）。届时 pin 在旧版的 BPT 若要接
  此类服务端，唯一通路是把 pin 抬到已支持 2026-07-28 的 SDK 版本——即面 2 的工作完成之后。
- 结论：BPT 侧无需任何即时动作；风险敞口由银芯侧面 2 的完工时点单向决定，方向与防火墙一致
  （银芯→黑池输出物升级，无回流）。

## 五、一句话总结

MCP 2026-07-28 对银芯是「近零即时冲击 + 一个明确的中期工程包」：Python 服务端被官方包
全权庇护，唯一手写协议栈 silver-core-sdk 需要在上游动作后做一次双模升级（且可跳过
2025-11-25 直达），SDK 既有的「不实现 roots/sampling/logging/SSE」从缺口翻转为规范背书
的正确姿态；BPT 侧零即时动作，风险敞口仅由 SDK 升级时点决定。
